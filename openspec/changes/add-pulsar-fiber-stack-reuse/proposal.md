## Why

Pulsar 目前只能让同一个 `Fiber` 通过 `reset()` 复用自身栈，调度器也只有一个临时回调 Fiber 槽；Fiber 被销毁后仍会直接释放栈，反复创建短任务会重复执行栈分配与对象构造。现有基线中，10,000 个默认栈 Fiber 的生命周期中位数约为创建 2.312 us、销毁 2.938 us，虚拟地址空间增加约 1.26 GiB，因此需要有边界、可观测且不破坏挂起语义的复用能力。

## What Changes

- 为 Pulsar 引入可插拔的栈分配接口以及有容量上限的栈池：按尺寸等级复用空闲栈，超大栈直通分配，支持主动裁剪、跨线程归还、统计信息，并保持 guard page 保护。
- 将现有 `Fiber::reset()` 的同对象复用纳入统一生命周期契约，确保 READY、RUNNING、挂在 I/O/Timer/WaitQueue 上或仍有外部引用的 Fiber/栈绝不被提前复用。
- 为调度器内部创建的回调 Fiber 增加有界的、按 worker 隔离的多槽 Fiber 缓存；只回收已经终止、已脱离等待源且没有外部别名的内部 Fiber，用户直接创建的 Fiber 不自动进入对象池。
- 增加池容量、命中/未命中、驱逐、当前缓存字节、在用峰值等观测指标，并补充并发、异常、停止、跨线程归还和内存保护测试。
- 增加同条件的冷/热池生命周期、突发创建、混合栈尺寸、大量休眠 Fiber、调度回调和上下文切换基准；所有性能结论使用相同构建、亲和性、负载和轮次进行前后对比。
- 保持现有 Fiber 构造、`resume/yield/reset` 语义、默认 128 KiB 栈以及 Scheduler 每 worker 单槽回调 Fiber 复用兼容；初始版本默认关闭栈池和多槽扩展，可由运行时配置显式启用，关闭后回退到直接分配器与既有单槽行为。
- 非目标包括可增长/分段栈、活跃栈共享、挂起 Fiber 的跨 worker 迁移、常驻任务消费协程池，以及将 SDK、2PC、同步 RPC、NodeServer、Raft、MVCC 或 RocksDB 工作改造成协程。

## Capabilities

### New Capabilities

- `pulsar-fiber-reuse`: 定义 Pulsar 栈池、调度器内部 Fiber 复用、生命周期安全、资源上限、可观测性、回退及可复现性能验收契约。

### Modified Capabilities

无。

## Impact

- 主要影响 `src/pulsar` 中的 Fiber 栈所有权、分配器与 Scheduler 内部回调 Fiber 生命周期，以及对应单元测试、集成测试、性能基准和文档。
- Gateway 可选择为 HTTP socket 的读/等待/写并发启用该能力；StrataKV 的线程池、事务、RPC、Raft 和存储架构边界保持不变。
- 不引入新的第三方依赖，不改变持久化格式或网络协议，也不要求现有调用方修改代码。
- 主要正确性风险是正在执行或仍被等待源引用的 Fiber 被错误回收、栈跨线程释放竞态、guard page 元数据丢失及缓存计数失真；规格与测试将这些条件设为强制不变量。
- 预期收益是热态短任务显著减少系统栈分配和 Fiber 构造成本；池化不能减少同时存活或休眠 Fiber 所必需的栈数量，并会以受控缓存字节换取吞吐。
- 回滚时关闭栈池与内部 Fiber 缓存，恢复直接栈分配；缓存资源在裁剪或 Scheduler 关闭时排空，无持久化迁移或数据回滚要求。
