# 构建与验证标准（适用于全部任务）

- 配置：`cmake -S . -B build/stratakv/release -DCMAKE_BUILD_TYPE=Release`；构建：`cmake --build build/stratakv/release -j`
- 每个任务只跑其声明的聚焦测试；全量 `ctest --test-dir build/stratakv/release --output-on-failure` 仅在 5.1/8.1 里程碑执行。
- 不重复跑二进制冒烟；入口行为每个里程碑验证一次。所有测试必须自终止（≤60s），挂住的测试按缺陷处理：`timeout 30 ./bin/<test>` 单独定位，先修测试再继续实现。
- 优先正确性：未跑出可复现数据前不得声称性能收益。保留工作树中与本病更无关的用户改动；`docs/` 为独立 Git 仓库。

## 3. Dynamic node lifecycle

- [x] 3.1 Add dynamic Region membership to the node: paired RegisterRegion/UnregisterRegion on NodeTxnScheduler with lifetime-safe peer handles, and TxnRecoveryManager resolving current Region handles instead of retaining the startup catalog. Implemented: scheduler stores weak peer handles (pre-existing) and finishes a Region's tasks on removal; TxnRecoveryManager now takes an injectable route resolver + revision callback (TSO dependency weakened to the TimestampOracle interface), rebuilds its LockResolver exactly once per topology-revision advance outside the lock, shares one topology view per scan round, and treats an empty view (pre-publication) as legal; NodeServer builds routes from the RegionRegistry's current peers (new `Peers()` snapshot enumeration). Also fixed three defects found by the new tests: `ShardRouter::Route` out-of-bounds on an empty shard list, `LockResolver::CheckPrimary` dereferencing a key with no current route, and a `Schedule` vs `OnRegionRemoved` race where `tasks_.at()` threw after the task was erased. Verify: new focused suite `stratakv-test-txn-recovery-dynamic` (route refresh tracks revision, empty routes skip secondary locks, concurrent unregister + recovery) passes 5 consecutive runs; the existing scheduler/recovery suites (`txn-scheduler`, `b3-recovery-check`, `b3-barrier-check`) plus transaction/Region regressions (11/11) pass.
- [x] 3.2 Complete node-side dynamic topology: metadata-driven bootstrap initializing all assigned peers from one validated metadata revision with atomic publication of the complete registry before recovery traffic is admitted (one failed peer leaves the registry unpublished and reports the failing Region), inbound Raft peer identity and epoch enforcement in dynamic mode with outbound headers already populated, and registry/lifecycle/header-validation metrics plus structured Region/Store/peer/epoch logging without raw keys or values. Verified: the end-to-end dynamic-cluster test boots three nodes from one metadata revision through `BootstrapNodeRegions` and serves transactions with headers enforced; `stratakv-test-region-registry`/`stratakv-test-region-dispatcher` cover lookup misses, conflicts, epoch rejects and retirement timeouts; the full suite (48/48) confirms static-mode Raft replication/election/ReadIndex/snapshot suites still pass.
