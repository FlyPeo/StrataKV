  DEBUG STATE (2026-09-17, final for this session): the split mechanism is functionally complete — all three replicas materialize phase-4, the child is published and acked, and the SDK successfully refreshes and regroups. The e2e timeout is NOT a deadlock: instrumented proof shows the SDK never sends a stale epoch after regroup (zero stale header constructions post-regroup), while the node logs 150+ rejections of pre-split-epoch requests inside the window between metadata commit and local AdminSplit apply (the split commit gap). The run "hangs" because three bounded retry budgets multiply: sender 8 attempts × 3 peers × 5s poll timeout, wrapped by the workload's 12 attempts, all inside the metadata-commit→apply window. Two hardening improvements follow directly: (a) shrink the commit-gap by having the metadata CommitSplit trigger an immediate AdminSplit proposal (push notification instead of client-driven proposal after commit), and (b) make the sender's refresh path short-circuit a rejected epoch to a fresh resolve without consuming the full peer rotation. All hardening fixes made this session stand on their own: leader-hint priority, router shared-locked storage map, channel-pool shared-lock + 8 channels + round-robin, poll()-based RPC timeout, TSO endpoint serialization.
